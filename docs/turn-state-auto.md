# 自动采集与最终注入轮次状态

更新日期：2026-09-18。

本文偏当前部署的使用与配置。分享给没有参考项目、准备改造自己 Sub2API 分支的开发者，请优先使用 [独立改造说明](turn-state-standalone-guide.md)，其中包含最小探测请求、出口验证、缓存和注入接点、IPv6池接口、网页配置及验收步骤。历史糖果题答案标签的更正也在独立说明中。

## 默认行为与账号设置

适用于 OpenAI OAuth / setup-token（两种账号授权凭据类型）。新建、导入账号默认开启独立开关 `codex_turn_state_auto_enabled`（是否自动采集状态），默认使用 Team 规则和购买代理 IPv4。显式关闭的导入账号保持关闭；旧账号缺少开关时仍保持原来的关闭行为。

账号编辑页面可以分别设置：

| 设置 | 默认值 | 手动选项 |
| --- | --- | --- |
| `codex_turn_state_profile`（采集规则） | `team`：只接受 332 字符 | `pro`：只接受原来的 292 字符 |
| `codex_turn_state_source`（采集出口） | `purchased`：购买代理，自动轮换国家，核验真实 IPv4 | `ipv6_pool`：保留原自建一次性 IPv6 池 |

Team 的 356、Pro 的 312，以及不符合所选规则的其他长度均被拒绝。还会检查字符、编码、签发时间和剩余有效期；长度命中不是对所有模型答题质量的保证。系统不自动发送完整质量评测问题。

状态按账号和实际模型隔离，保存规则、出口方式和上游账号身份摘要。切换账号身份、Team/Pro 或出口方式时，不应用不匹配的缓存；采集完成后再次核对账号开关和设置，避免发布已经被关闭或切换的任务结果。旧版本的 Pro 缓存仅能在明确选择 Pro＋IPv6 池时继续使用。

## 购买代理采集与国家轮换

候选国家默认20个：德国、英国、法国、新加坡、南非、巴西、阿联酋、美国、日本、荷兰、加拿大、澳大利亚、意大利、西班牙、瑞典、挪威、瑞士、波兰、韩国、印度。网页可调整，不把国家当作永久成功或失败的规则。2026-09-18中午同一Team账号的gpt-6-astra补测：德国两次独立采集均首次332，英国首次332，法国先356再332；荷兰与加拿大各三次356，仍保留在默认轮询中。这是小样本观察，不是固定成功率；新增候选不代表已经逐国实测，实际出口供应取决于代理商。

升级不会覆盖已保存的国家列表或显式环境配置；已有部署需在网页手动保存新列表 `DE,GB,FR,SG,ZA,BR,AE,US,JP,NL,CA,AU,IT,ES,SE,NO,CH,PL,KR,IN`。默认每轮9次不变，连续失败时通常一轮遍历3国，再冷却继续后续国家；增加国家不等于提高单轮尝试数。原轮换位置仍保留，不保证修改后立即从首国开始。

1. 每次采集生成新的随机代理会话编号，不复用上一轮认证会话编号。
2. 若配置了前置 SOCKS5（代理连接协议），先连接前置代理，再连接购买代理；没有绕过购买代理的直连回退。
3. 通过购买代理查询目标域名的 IPv4 地址，加密连接仍核验 `chatgpt.com` 的服务器证书。
4. 在目标连接上查询 `/cdn-cgi/trace`（来源地址和国家回显接口），确认实际来源为 IPv4 且国家匹配；随后沿同一加密连接发送最小探测。
5. 实际 IPv4 地址通过 Redis（共享缓存服务）作一小时去重，多个账号或实例不会在此期间重复探测同一已领取地址。地址或国家不匹配也作为采集失败记录。
6. 探测只发送 `Reply OK.`，不复制用户正文、旧状态、旧会话标识或 Cookie（浏览器会话凭据）；拿到响应头即关闭连接，不等待完整模型回答。
7. 同一账号、模型、规则和出口方式下，连续三次不合格或采集失败后切换下一候选国家。计数和国家位置跨采集轮次、实例及重启保存在共享缓存中；成功后清零连续失败数并保存该状态。
8. 401/403（认证或访问失败）、429（限流）会结束当前采集轮次，不持续换国家请求。其他失败在本轮预算内继续尝试，预算耗尽后进入重试冷却。

自建 IPv6 池仍使用原租用、探测、退役流程，不改动原独立服务，也不自动混入购买代理模式。

## 提前刷新、有效期与并发

沿用原时效规则，从状态值内的签发时间起算 60 分钟；不是从保存时间重新计算。

- **默认签发满48分钟开始后台尝试获取新值**，网页可设1–59分钟；这是签发后的经过时间，不是剩余有效期。修改后重新计算已有头的刷新时间，到期时间仍为签发后60分钟。
- 新值获取失败时继续使用仍有效且匹配的旧值；过期后不再注入旧值。
- 每 30 秒检查最近两小时有业务请求的账号模型。超过两小时未使用的模型停止主动刷新，避免无限消耗；下次业务请求重新激活。
- 每轮默认最多 9 次采集尝试，最多 4 个任务并发；每轮整体限时 5 分钟，单次探测限时 30 秒。
- 一轮失败后至少间隔两分钟重试。已有任务结束会立即调度待处理目标，不必等下一次周期检查。
- 共享缓存中的账号模型锁避免多个进程同时采集同一目标。

### 业务响应触发重采集

网页“收到异常响应头立即重新采集”默认开启，可关闭。Pro请求使用本模块缓存的292状态后，响应状态头长度为312；或Team使用332后返回356时，立即停用该请求实际使用的旧值并后台重采集，不等48分钟计时。数字是 `X-Codex-Turn-State`（轮次状态头）的长度，不是HTTP状态码；这是可配置的经验规则，不证明上游存在某种确定的撤销协议。

同时核对账号、实际模型、规则、出口方式、上游身份和发送的原值。共享缓存以原子比较更新（比较与写入不可被其他请求插入）的方式标记失效；多个并发响应只触发一次，迟到响应不能停用已替换的新值。已停用值在原有效期内不能重新入库；客户端回带这个已知旧值时也会剥离。有效期未满不再是继续使用该值的理由。新值未采集成功时，正常业务请求仍走原有流程，不能承诺此时一定已有合格头。

监测覆盖普通HTTP/流式请求、账号测试的上游返回及新建WebSocket（双向长连接）握手响应；复用连接不重复把历史握手头当成新信号。WebSocket消息帧里的任意同名字段不作为响应头处理。处理不读取或关闭回复正文，不重放请求，不中断当前回复；采集任务仍受并发上限控制，满额时排队。检测记录显示“响应触发重采集”，与采集候选失败区分。无此响应头、合格长度或其他未配置长度不会触发。已排除的模型、关闭自动采集的账号不参与。

第一次收到该账号某模型的业务请求时启动后台采集。**首次请求不等待采集完成，仍走原有请求流程**。未获得匹配的有效值时，不作本模块的强制覆盖；关闭开关也保留原有转发行为。

默认不采集 `codex-auto-review`、`gpt-5.6-terra`、`gpt-5.4`。网页提供三个模型的采集开关，也可编辑完整模型名称的排除列表（不区分大小写，不支持通配符，最多100个；清空表示全部允许）。匹配实际上游模型名称，不把 `gpt-5.4-mini` 等其他名称一并排除。排除后跳过自动、手动采集及本模块缓存头注入；普通业务请求仍走原有流程。保存时取消被排除模型的正在运行和排队任务，历史记录保留，缓存按原到期时间过期。重新开启并保存后，由后续模型请求或手动按钮激活。

采集器不是上游模型目录同步器：旧实现会在模型被请求或手动激活后持续重试，活跃窗口为两小时，没有自动识别下线模型的机制。日志中400只说明上游拒绝了探测，不能单凭状态码判断下线；上述默认排除是可调整的运行策略，不宣称模型永久只返回某种长度。旧网页配置缺少新增字段时自动采用48分钟和上述三个默认排除项；已明确保存的值保持不变。

也可在账号编辑页的“配置”面板中填写实际模型（默认 `gpt-6-astra`），点击“立即采集／重新获取”，无需等待业务请求。必须先保存账号开关、规则、出口及全局采集配置。按钮加入后台任务；并发满时排队，已有同账号模型任务时复用，不重复发起。手动任务跳过有效缓存的免采集判断，但不删除旧头；失败仍保留未过期旧头。检测过程、轮换国家及结果沿用现有记录，不自动发送完整问答质量测试。

普通请求、流式请求和兼容桥继续在原有最终发送入口应用覆盖。WebSocket（双向长连接协议）继续在握手及轮次边界接入，连接复用条件包含状态摘要，避免复用携带旧状态的连接。账号原有防串号逻辑保留。

## 页面状态与检测记录

账号编辑页显示保存后的开关状态、各模型采集状态、当前字段长度、来源国家、到期时间、剩余有效期、提前刷新倒计时及失败后的重试倒计时。倒计时用服务端时间校正浏览器时间偏差。

“查看检测记录”按钮按需读取最近 7 天内、最多 200 条记录，包含模型、Team/Pro、出口方式、国家、实际地址、响应状态、字段长度、耗时和失败摘要。不会返回原始状态字段、账号令牌或代理密码。记录存放于共享缓存，重启后仍可查询；整个记录列表在账号七天没有新检测时过期。

管理员接口（沿用原管理员权限）：

- `GET /api/v1/admin/accounts/{id}/turn-state`：配置可用性和模型状态。
- `GET /api/v1/admin/accounts/{id}/turn-state?history=1`：额外读取检测历史。
- `POST /api/v1/admin/accounts/{id}/turn-state/acquire`：管理员手动启动采集，请求体 `{"model":"gpt-6-astra"}`，返回 `queued: true` 仅表示任务已受理，不代表采集成功。
- `GET /api/v1/admin/accounts/turn-state/settings`：读取脱敏后的全局采集配置。
- `PUT /api/v1/admin/accounts/turn-state/settings`：校验、加密保存并应用网页采集配置。

已成功缓存的模型通过共享索引可跨实例显示；正在采集或排队的瞬时状态仍来自处理管理请求的实例。检测记录中的“通过采集规则”指探测候选通过格式及时间规则，不代表完整业务问答已经验证。

## 部署配置

### 网页配置（推荐）

进入“账号 → 编辑 → 自动采集并注入轮次状态”，点击开关旁的“配置”。展开的面板为**所有账号共用的采集服务配置**，不改变业务请求代理；账号仍分别选择 Team/Pro、IPv4/IPv6 及是否启用。

- IPv4：启用购买代理，填写主机名与端口、包含 `{country}` 和 `{session}` 的用户名模板、密码及候选国家。
- IPv6：启用自建池，填写 HTTPS 池地址和管理密钥；自签名 CA 证书可直接粘贴或上传文件，无需服务器文件路径。
- 前置代理可选，必须是业务服务器可访问的 SOCKS5 地址。已配置的地址可能包含密码，不回显；留空保持，勾选清除才删除。
- 刷新时间：填写请求头签发后多少分钟开始刷新，默认48，可设1–59。模型采集开关与“不采集的模型”列表联动，修改后需保存；这些设置由所有账号共用。
- 异常响应触发：默认开启，接口字段 `refresh_on_rejection`（异常响应是否触发重采集）为布尔值；旧配置没有该字段时采用开启，明确关闭后重启仍保留。关闭不恢复已经停用的旧值。
- 点击“保存采集配置并生效”，当前服务直接使用新配置，不需终端或重启；其他实例通常15秒内同步。账号开关和下拉选择仍通过“保存账号”提交。
- 密码和池密钥留空保留原值，不回传网页。配置整体加密存储在数据库，敏感请求正文不写入审计日志；关闭服务选项保留凭据以便再次启用。
- 保存验证配置格式和证书，不主动发模型测试请求；网络连通性、代理有效性和实际采集结果以“查看检测记录”为准。
- 从未网页保存时兼容原环境变量；保存后数据库配置优先，重启后仍保留。需保留服务器原有 `JWT_SECRET`（登录签名密钥，也是本配置加密的密钥来源）；多实例须使用相同值。更换此密钥后旧配置将无法解密。

以下环境文件方式只作为旧部署兼容，不再是配置必需步骤。

购买代理所需环境变量（程序启动时读取的参数）：

| 名称 | 功能 |
| --- | --- |
| `TURN_STATE_PROXY_HOST` | 购买代理入口，格式为主机名和端口 |
| `TURN_STATE_PROXY_USERNAME` | 购买代理用户名模板，必须包含 `{country}`（国家代码）和 `{session}`（每次随机会话编号） |
| `TURN_STATE_PROXY_PASSWORD` | 购买代理密码，仅通过私有部署配置提供 |
| `TURN_STATE_PROXY_COUNTRIES` | 逗号分隔的候选国家代码，默认 `DE,GB,FR,SG,ZA,BR,AE,US,JP,NL,CA,AU,IT,ES,SE,NO,CH,PL,KR,IN`，最多20个 |
| `TURN_STATE_PROXY_UPSTREAM` | 可选前置代理，例如本地测试使用 `socks5://127.0.0.1:7897`；海外服务器可留空 |
| `TURN_STATE_POOL_ATTEMPTS` | 两种采集方式共用的每轮尝试预算，默认 9，范围 1–30 |
| `TURN_STATE_POOL_CONCURRENCY` | 单实例任务并发，默认 4，范围 1–16 |
| `TURN_STATE_REFRESH_AFTER_MINUTES` | 签发后开始刷新的分钟数，默认48，范围1–59 |
| `TURN_STATE_EXCLUDED_MODELS` | 不采集的完整模型名称，逗号分隔；未设置时默认 `codex-auto-review,gpt-5.6-terra,gpt-5.4`；显式空值表示不排除任何模型 |

原 IPv6 池连接参数全部保留：`TURN_STATE_POOL_URL`（加密池地址）、`TURN_STATE_POOL_TOKEN`（管理密钥，至少32字符）、`TURN_STATE_POOL_CA_FILE`（自建证书的信任文件路径）。仅配置购买代理时无需配置 IPv6 池；仅配置池时，可以在账号上手动选择 IPv6 池。至少一种方式完整配置且共享缓存可用后，本模块才能启动。

仓库的 `deploy/turn-state-proxy.env.example` 仅为模板，不含真实密码。把私有购买代理配置放在业务服务器的 `/etc/sub2api-turn-state-proxy/sub2api.env`，可以叠加 `deploy/docker-compose.turn-state-proxy.yml`（购买代理环境文件的容器编排扩展）：

```sh
docker compose -f YOUR_EXISTING_COMPOSE_FILE -f deploy/docker-compose.turn-state-proxy.yml up -d sub2api
```

同时保留 IPv6 池配置时，继续准备原 `/etc/sub2api-turn-state-egress/sub2api.env` 及 `ca.crt`，并叠加原 `deploy/docker-compose.turn-state.yml`：

```sh
docker compose -f YOUR_EXISTING_COMPOSE_FILE -f deploy/docker-compose.turn-state.yml -f deploy/docker-compose.turn-state-proxy.yml up -d sub2api
```

只更新业务容器，不重建或修改独立 IPv6 池服务。若两个环境文件均设置采集预算，以上顺序以购买代理文件的值为准。

国内本地测试需要前置代理；容器里的 `127.0.0.1` 指容器自身，不能直接当作宿主机的 7897 端口。部署时按实际可达地址配置前置代理，不把开发机的地址直接复制到海外服务器。

拉取源码或镜像不会自动获得代理密码和池密钥。配置缺失或无效时，页面显示所选方式不可用，不谎报采集成功。仅环境变量改变时需要重启业务服务；网页保存无需重启，且优先于环境变量。

## 验证

测试覆盖 Team/Pro 独立规则、旧 Pro 缓存兼容、账号模型和身份隔离、默认48分钟及自定义时间刷新、模型排除与重新开启、运行中配置变更取消排除任务并重算刷新时刻、失败保留旧值、跨轮次国家轮换、共享历史和缓存索引、关闭或切换设置时不发布、96个账号模型目标的并发调度，以及两种代理采集方式。

购买代理测试使用真实加密测试服务器，检查 IPv4 目标、同连接来源核验、国家匹配、地址去重、无旧状态／凭证泄漏，以及只读响应头、不等待流式生成的行为。真实账号测试需要显式环境开关，默认测试不会访问真实服务或消耗账号。

2026-09-18 的脱敏实测见 `docs/turn-state-live-test-20260918.md`。地区命中率会变化，不提供固定成功率或固定地区恢复周期的保证。
