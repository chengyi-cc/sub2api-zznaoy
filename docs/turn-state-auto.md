# 自动采集与最终注入轮次状态

实现日期：2026-09-17。

## 功能范围

为 OpenAI OAuth / setup-token（两种账号授权凭据类型）增加独立的账号开关 codex_turn_state_auto_enabled（是否启用自动轮次状态采集）。新创建、导入的适用账号默认开启；显式配置 false（关闭）时保留关闭。旧账号没有该字段时维持关闭，不迁移改变旧账号行为。

开启后按本地账号编号、实际模型名称分别管理 X-Codex-Turn-State（上游轮次状态头）。另外保存上游账号与工作区身份的摘要，防止本地账号重新绑定后使用已知属于旧身份的值。

- 292 字符：按用户指定规则接受。
- 312 字符：拒绝，并在本轮预算内换新出口。
- 其他长度、非法格式、未知签发时间、过期或剩余不足两分钟：拒绝。
- 时效从值内的签发时间起算一小时，不从保存时间起算。
- 不额外发起模型问答质量验证；“可用”表示通过以上工程规则。

## 操作体验

账号编辑页面增加“自动采集并注入轮次状态”开关和模型状态列表，保存后生效。

首次对该账号的某模型发起业务请求时，后台开始采集；管理端账号测试请求也接入同一最终发送入口。**首次请求不会等待采集，继续原有转发方式**。采集成功后，后续请求自动使用本账号、本模型的值。

页面会显示出口池未配置、等待请求、采集中、可用、刷新中、失败或过期。开启不等于已获取成功。

采集失败不会中断原来的业务请求。没有有效匹配值时不做新的强制覆盖，原有请求头处理仍然生效。关闭开关后不再应用本功能；已在途请求和已建立网络连接不会在管理员点击时被强制中断。

## 刷新与隔离

使用 Redis（共享缓存服务）保存状态，有效期随签发时间到期；通过分布式锁避免多个进程同时为同一账号模型采集。

- 每 30 秒检查本实例最近 15 分钟使用过的账号模型。
- 剩余五分钟时后台刷新。
- 每轮默认最多尝试 3 个新出口，最多并发 4 个采集任务。
- 一轮失败后至少冷却两分钟；未使用的模型不会一直消耗采集请求。
- 一次采集租用一个独立出口，请求完成后退役；采集请求不携带客户端正文、旧状态、旧会话或 Cookie（浏览器会话凭据）。
- 使用固定的极短探测内容，同账号同模型正常请求上游；会产生额外上游调用与可能的用量。
- 新值保存前复查账号是否仍启用。失败不覆盖仍有效的旧值。
- 后台任务使用最新账号访问凭证，读取上游身份后再请求。

模型名称以实际请求正文中的模型为准，不进行大小写合并或通配符复用。账号或模型切换时重新查询状态。

原有普通请求、流式请求和兼容桥统一从最终请求发送入口接入。WebSocket（双向长连接协议）握手也应用匹配状态，连接池的兼容条件加入状态摘要，避免重用带旧状态的握手连接；同一长会话换模型或换状态时，在轮次边界重新获取匹配连接。

如果启用了第三方传输插件，请额外确认该插件尊重主程序提供的头字段。主程序在传入插件前已经覆盖，但不能控制仓库以外插件内部自行重写字段的行为。

## 一次性部署配置

仅拉取源码或镜像不会自动获得服务器私密调用密钥。需要把新池生成的两个文件放到业务服务器：

- /etc/sub2api-turn-state-egress/sub2api.env：私密参数，不提交版本库。
- /etc/sub2api-turn-state-egress/ca.crt：新池的公开信任证书。

环境变量（启动程序时读取的配置参数）：

| 名称 | 功能 |
| --- | --- |
| TURN_STATE_POOL_URL | 加密出口池地址，必须是 HTTPS 地址且不含路径 |
| TURN_STATE_POOL_TOKEN | 管理密钥，至少 32 字符 |
| TURN_STATE_POOL_CA_FILE | 自建证书的信任文件；使用公共证书时可省略 |
| TURN_STATE_POOL_ATTEMPTS | 每轮尝试次数，默认 3，范围 1–10 |
| TURN_STATE_POOL_CONCURRENCY | 单实例采集并发，默认 4，范围 1–16 |

仓库提供 deploy/docker-compose.turn-state.yml（只添加连接参数和公开证书挂载的容器编排扩展）。以业务服务器已有主编排文件为基础，显式叠加它：

    docker compose -f YOUR_EXISTING_COMPOSE_FILE -f deploy/docker-compose.turn-state.yml up -d sub2api

这会更新 sub2api 容器，必须在准备更新业务服务时执行；不会更新旧 IPv6 代理。本次不能默认替用户选择同一服务器上的两个业务实例，也不能让密钥随源码推送。

如果不使用容器，在业务服务启动环境中加载对应参数，并让运行用户能读取公开证书。配置无效或服务未配置时，本功能停用且页面提示，主服务继续启动。

## 测试步骤

1. 部署包含本次提交的新 sub2api，并加载新池连接参数。
2. 打开一个适用账号的编辑页面，确认不显示“出口池尚未配置”。
3. 新导入账号默认开启；测试旧账号时手动开启并保存。
4. 用该账号请求一个目标模型（也可以使用管理端账号测试），查看状态从等待或采集中变为可用。
5. 查看失败原因：312 字符被拒绝会换出口；没有满足规则的结果会进入冷却，不会谎报成功。
6. 再发同模型请求；测试另一个模型时应出现独立记录。
7. 关闭开关，确认恢复原流程；测试刷新、过期和换账号重试。

诊断接口：GET /api/v1/admin/accounts/{id}/turn-state（需要原有管理员权限），只返回配置状态、模型名称、到期时间和错误摘要，不返回原始状态、访问凭证或代理密码。

多实例部署的有效状态由共享缓存统一保存，但面板模型列表来自处理当前管理请求的实例内存；另一实例刚采集的模型可能在本实例尚无列表项，其有效值仍可在业务请求时读取。

## 验证边界

自动化测试覆盖长度、时效、账号模型隔离、上游身份变化、最终覆盖、并发与分布式锁、关闭时不发布、刷新失败保留旧值、加密代理采集与释放、账号开关保存。

出口池单独测试地址批量生成、退役不复用、异常回收和不删除外部地址；另外提供真实网络出口验证脚本。

部署新池与跑测试不代表已经用生产账号验证所有模型的实际效果；真实模型测试由使用方在配置好更新后的业务实例后完成。
