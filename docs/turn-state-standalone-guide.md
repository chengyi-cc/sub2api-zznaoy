# Sub2API 请求头自动采集与注入：独立改造说明

更新：2026-09-18。功能基线：`ea6f8f241`（实现手动采集按钮的代码版本）。

本文面向维护自己 Sub2API 分支的开发者。不需要原参考项目、不需要原聊天记录，也不需要本文作者的账号或服务器。代码文件名仅用于定位实现职责，你的分支没有同名文件时，应在对应的请求发送位置接入。本文不是可以直接运行的完整源码包。

## 1. 做什么，以及目前知道什么

目标是独立增加一项可按账号开关的功能：通过轮换出口发送最小探测，读取上游响应中的 `X-Codex-Turn-State`（上游返回的不透明轮次状态字段），筛选后按账号与实际模型缓存，再在业务请求最终发送前用它覆盖同名请求头。

这里获取的是**一个响应头字段的值**，不是复制浏览器的整套请求头，也不是把浏览器登录凭据注入其他账号。必须使用待采集账号自己的有效授权进行探测。原始状态值不应跨账号共用。

目前采用以下经验筛选规则：

| 账号规则 | 接受的字符串长度 | 已观察到但拒绝的长度 |
| --- | ---: | ---: |
| Team（团队账号规则，默认） | 332 | 356 |
| Pro（个人专业账号规则，可手动切换） | 292 | 312 |

其他长度也拒绝。长度按字段值去掉首尾空白后计算；这里只接受可打印 ASCII（单字节字符），因此字节数与字符数相同。

这是现有实现的筛选策略，不是上游公开协议或所有账号、模型都适用的能力保证。没有证据确认字段内部决定了模型能力，也没有解密或验证它的签名。“新地址一定先出332”“某地区固定多久恢复”“IPv6一定无效”都不能当作已证实结论。

2026-09-18 一个 Team 账号、模型 `gpt-6-astra` 的实测中，美国曾连续返回356，稍后6次尝试出现4次332、1次356、1次连接失败。另一次使用新采集模块，阿联酋3次356后转美国，第1次获得332。原自建 IPv6 池当时3个地址均为356。它们说明结果会变化，不能推导长期命中率。

### 关于之前糖果题的验证标签

历史测试把回答“21”作为预期标签，并确实记录到某些332样本回答21；这只能表述为“符合当时预期标签”，不能据此证明答案正确或模型质量更高。

按题目给出的数量和配对条件，数学上的保证值实际上是29：可以取全部西瓜12颗、圆形苹果7颗、圆形桃子9颗，共28颗，仍没有任何五角星苹果或桃子，因而没有所要求的配对。一般地，避免配对时，圆苹果7与星桃子6最多选一侧，圆桃子9与星苹果7最多选一侧，上限为 `12 + max(7,6) + max(9,7) = 28`，因此29颗才保证满足。

后续质量评测应另用答案已核实的一组题。不要把“21正常、29异常”写入生产筛选规则；当前模块本身也不依据完整问答答案决定保存。

## 2. 用户最终操作

1. 创建或导入 OpenAI 的 OAuth / setup-token 账号（分别指可刷新授权与直接授权凭据类型）；新账号默认开启，默认 Team 与购买代理 IPv4。
2. 在账号编辑页的开关旁点“配置”，填写全局采集出口。此配置所有账号共用，但各账号的状态缓存和选择独立。
3. 保存全局配置，再保存账号上的开关、规则和出口选择。
4. 等待该账号首次处理某模型请求，或在配置面板输入实际模型，点“立即采集／重新获取”。模型默认 `gpt-6-astra`，可修改，须使用账号确实可用的模型。
5. 在“查看检测记录”确认实际国家、地址、响应码、字段长度和采集结果；页面同时显示剩余有效期和刷新倒计时。

**创建账号本身不立即探测。** 首次业务请求只触发后台采集，不阻塞等待；还没有合格状态时按原流程转发。手动按钮可以在没有业务请求时启动采集，复用正在进行的同账号模型任务，并发满时排队。手动刷新跳过“缓存很新所以无需获取”的判断，但不先删除有效旧值。

## 3. 独立实现需要什么

- 现有 Sub2API 的账号仓库、授权刷新能力、管理员认证和最终请求发送入口。
- Redis（多个进程共享的缓存服务）：缓存状态、采集互斥锁、出口去重、国家轮换与历史记录。
- 现有数据库的设置存储：保存加密后的全局采集配置；无需把代理密码写进账号导出数据。
- 支持 SOCKS5（代理连接协议）的购买代理，提供国家选择及随机会话用户名。只做购买 IPv4 模式，不需要自建 IPv6 服务器。
- 可选：一台有可用 IPv6 前缀和出站路由的独立池服务器；它不是 Sub2API 自带能力，具体接口见第8节。

采集出口与业务出口是两件事。本功能仅改变探测请求的出口，业务请求仍走原账号的代理；采集值在业务请求最终发送前注入。特定样本跨出口使用曾被测试，不代表上游承诺永远支持。

## 4. 到底怎样获取字段

### 4.1 最小探测请求

请求地址：`POST https://chatgpt.com/backend-api/codex/responses`（当前账号模型请求入口）。它不是公开稳定的第三方兼容协议，接口变化需要维护。

请求头至少包含：

```text
Authorization: Bearer <待采集账号的有效访问令牌>
Chatgpt-Account-Id: <该账号所属的上游账号标识，如适用>
Content-Type: application/json
Accept: text/event-stream
Accept-Encoding: identity
Session-Id: <每次新生成的会话标识>
```

`Authorization` 用于身份认证；`Chatgpt-Account-Id` 用于选择上游账号；`Session-Id` 用于隔离探测会话。客户端标识字段如 `User-Agent`（客户端类型和版本）、`Originator`（调用来源）、`Version`（客户端版本）应沿用你的网关规范。自动采集从业务请求中只提取允许的身份与客户端字段；手动采集使用服务端默认客户端标识。

请求体采用 JSON（结构化文本格式）：

```json
{
  "model": "gpt-6-astra",
  "instructions": "Reply briefly.",
  "input": [
    {"role": "user", "content": [{"type": "input_text", "text": "Reply OK."}]}
  ],
  "stream": true,
  "store": false
}
```

`stream` 开启流式返回，`store` 关闭此次请求的存储选项。不携带用户完整对话、旧的 `X-Codex-Turn-State`、旧会话标识或 Cookie（浏览器会话数据）。

读取响应状态码与 `X-Codex-Turn-State` 即可结束，不等待生成完整回答。尤其不能先完整问一遍题再看长度。购买代理实现读取头部后先关闭连接，再关闭响应体，避免为了复用连接而继续读取生成内容；这仍不代表请求完全不产生用量。

### 4.2 IPv4 的正确连接链路

```text
Sub2API → 可选前置代理 → 购买代理 → chatgpt.com 的 IPv4 地址
```

购买代理配置示例，均为占位内容：

```text
地址：proxy.example:7778
用户名模板：YOUR_PREFIX_{country}___5_{session}
密码：自行填写
国家：DE,GB,FR,SG,ZA,BR,AE,US,JP,NL,CA,AU,IT,ES,SE,NO,CH,PL,KR,IN
前置代理：可留空，或 socks5://server-reachable-proxy:7897
```

`{country}` 替换为国家代码，`{session}` 每次替换为新随机编号；当前实现采用4字节安全随机数编码成8个十六进制字符。`___5_` 是特定代理商示例格式的一部分，不是通用协议，其他代理商须适配自己的会话格式。

国内部署若无法直连购买代理，先通过前置代理连接购买代理，不能只配置前置代理后误以为已使用购买出口。服务器上的 `127.0.0.1` 指服务器自身，容器中的该地址指容器自身，不是你的开发电脑。

购买模式每次按以下顺序执行：

1. 为目标国家生成一个新会话用户名，通过 SOCKS5 建立购买代理连接。
2. 通过购买代理向 `https://cloudflare-dns.com/dns-query?name=chatgpt.com&type=A` 查询 DNS（域名到地址的解析）。选取有效公网 IPv4；目标地址解析缓存最多60秒。代理本身是否提供真正新出口仍需下面验证。
3. 连接该 IPv4 的443端口。TLS（加密连接）继续用 `chatgpt.com` 作为证书验证名称，保留该域名的 HTTP 主机信息，不能关闭证书验证。当前实现使用 HTTP/1.1（按顺序读写响应的协议版本）。
4. **在这条连接**先请求 `GET /cdn-cgi/trace`（目标服务回显来源信息的接口），读取 `ip`（真实出口地址）和 `loc`（国家代码）。该请求不需要账号令牌。
5. 实际地址必须是 IPv4，实际国家必须匹配所选国家；不匹配则计失败。不能用另一条“查IP”连接代替此证据。
6. 用 Redis 的 `SET NX`（仅在键不存在时写入）领取真实地址，保留1小时，避免不同账号和实例重复探测已使用地址。随机会话不同不保证出口不同，重复地址也算失败。
7. 沿**同一条已验证连接**发送最小模型探测，获取字段并关闭连接。来源验证连接被关闭、失败或响应异常时，放弃此次尝试，不静默另开一条未验证连接继续。

DNS 查询地址、来源回显接口等是当前具体实现选择；你的网络环境需要能通过代理访问它们。任何阶段失败都不自动回退到直连目标模型接口。

## 5. 筛选与国家轮换

合格候选除长度规则外，还需满足当前格式检查：

1. 每个字符在可打印 ASCII 范围 `0x21` 到 `0x7e`。
2. 可按 URL 安全 Base64（使用适合网址字符的二进制编码）解码，允许带或不带填充。
3. 解码后长度至少73字节，首字节为 `0x80`，且 `(解码长度 - 57) % 16 == 0`。
4. 将第2至9字节按大端无符号整数读取为 Unix 秒数（自1970年起的秒数），作为观察到的签发时间；支持区间为2020年至2100年。
5. 签发时间不能超过本机时间30秒；按当前1小时本地有效期规则，采集时剩余时间必须大于2分钟。

这属于格式和时效筛选，**不是密码学验签**。字段虽然呈现类似加密令牌的结构，本实现没有其密钥，不修改内部内容，也不伪造签发时间。1小时是本系统采用的缓存策略，不宣称已经证明上游恰好在该时刻失效。

国家默认顺序（2026-09-18扩充至20个）：`DE` 德国 → `GB` 英国 → `FR` 法国 → `SG` 新加坡 → `ZA` 南非 → `BR` 巴西 → `AE` 阿联酋 → `US` 美国 → `JP` 日本 → `NL` 荷兰 → `CA` 加拿大 → `AU` 澳大利亚 → `IT` 意大利 → `ES` 西班牙 → `SE` 瑞典 → `NO` 挪威 → `CH` 瑞士 → `PL` 波兰 → `KR` 韩国 → `IN` 印度，再循环；网页可改，最多20个。每个账号、模型、规则、来源组合单独记录国家位置与连续失败次数。

中午同一Team账号的gpt-6-astra补测：原列表的新加坡、美国、日本合计8次356及1次连接失败，德国两次独立采集均首次332，英国首次332，法国先356再332；荷兰与加拿大各三次356。默认扩充多个地区以改善覆盖，不能把短期失败当成永久不可用，荷兰、加拿大也保留在默认轮询中。新增候选不代表已经逐国实测，实际出口供应取决于代理商。已保存列表不会被升级覆盖，需要在网页保存新列表；增加国家不改变每轮9次预算，后续国家通过跨轮次轮换到达。

- 任意不合格长度（Team 包括356）或采集失败，连续计数加1。
- 第3次失败后切换下一国家，失败计数归零；不足3次时下次继续当前国家。
- 合格候选保存并清零失败数，**成功不切国家**；后续刷新仍从该国家开始。
- 国家位置和失败计数写入共享缓存，有效期7天，跨轮次和服务重启保留。
- 401/403（认证或访问失败）与429（限流）终止当前轮次；不在该轮中持续换国家。自动调度后续仍可能按冷却策略再尝试，不等于永久停用账号。

## 6. 状态存储、刷新与并发

状态主键按本地账号ID与**实际上游模型名称**划分。若网关有模型别名映射，自动采集使用映射后的名称，手动输入也应填这个名称。

缓存记录包含：原始字段值、实际模型、Team/Pro、IPv4/IPv6来源、上游身份摘要、签发时间、采集时间、到期时间、国家、实际来源地址。上游身份摘要由上游账号和工作区标识生成；没有这些标识时用授权摘要作后备。只匹配本地账号ID还不够，重新授权为其他身份时不能沿用旧值。

当前存储约定，键名可自行调整但需保证各实例一致：

| 内容 | 隔离范围与保留方式 |
| --- | --- |
| 状态值 | 账号ID＋模型摘要；缓存到签发满60分钟 |
| 采集互斥锁 | 账号ID＋模型摘要；310秒租期；随机锁值，释放时核对所有者 |
| 已使用IPv4 | 真实地址摘要；1小时，全局共享 |
| 国家轮换 | 账号＋模型＋规则＋来源；7天 |
| 历史记录 | 每账号最近7天最多200条；共享列表 |
| 模型索引 | 每账号已有缓存模型集合；用于其他实例读取状态 |

后台调度默认：每轮9次尝试（网页可设1–30），单实例同时4个任务（可设1–16），单轮最多5分钟，单次探测最多30秒，失败重试冷却2分钟。并发槽空出时立刻调度待处理目标，也每30秒扫描一次。

签发满30分钟进入刷新窗口；刷新失败保留未过期旧值，到60分钟不再注入。最近两小时被业务请求或手动采集激活的目标参与主动刷新；长期闲置停止自动消耗，下次请求再激活。

缓存、去重与互斥锁在多实例间共享；并发上限和等待队列是**每个进程本地**的，不是全站统一4个任务。当前每进程最多跟踪2048个目标，排队状态也不保证跨实例可见。进程重启后，已保存状态和历史仍可读，但内存中的待采集任务与活跃列表须由新请求重新激活。

## 7. 怎样接入你自己的 Sub2API

建议拆为独立采集模块、账号集成层、管理员接口和网页组件，只在必要的业务出口接入。

### 必须接的四类位置

1. **账号创建与导入**：初始化三个账号扩展字段；显式关闭保持关闭，原有老账号缺少开关时保持关闭，避免升级后突然开始采集。
2. **普通请求与流式请求的最后发送位置**：完成账号选择、模型映射、身份检查和已有头处理后，按账号身份与模型读取匹配缓存，在最终发送前替换字段。确保后续没有其他中间层重新覆盖。
3. **失败重试／换账号的位置**：重新选定账号后重新匹配，不能携带上个账号的状态。已有轮次来源检查和防串号机制应保留，不要通过关闭它们实现覆盖。
4. **WebSocket（双向长连接）**：在握手和每次模型轮次更新处应用，连接复用的兼容性比较应包含状态摘要；必要时重建连接，否则网页显示换头但旧连接仍携带旧状态。

流程示意：

```text
业务请求 → 选账号 → 解析实际模型 → 原有身份/状态检查
         → 查匹配且未过期的采集值 → 最终头部替换 → 上游发送
                  └→ 缺值或进入刷新期：后台采集，不阻塞本次请求

手动按钮 → 管理员认证 → 读取已保存账号配置 → 校验授权和采集出口
         → 任务去重/排队 → 新出口最小探测 → 检查候选
         → 再核对账号开关、身份、规则和来源 → 发布新缓存
```

采集完成前再次核对账号开关及身份，避免账号关闭、换授权或切换规则后，旧任务仍发布结果。功能关闭、出口未配置、没有可用状态时保留原业务处理流程，不让新增采集失败影响基础转发。

| `frontend/src/components/account/TurnStateSettingsPanel.vue` | 全局出口配置、证书上传、模型输入、手动采集按钮 |
| `frontend/src/components/account/EditAccountModal.vue` | 加载与保存账号扩展字段 |

不要只复制上述某个按钮组件或采集文件。还需注册依赖、路由、账号更新字段，加入服务退出时的任务取消，并检查你分支的最终传输入口是否不同。

## 8. 可选的独立 IPv6 池接口

没有原池项目时可先完成 IPv4 模式。若要自己实现兼容池，下面是当前 Sub2API 客户端的接口契约；池服务必须另行部署，不能仅靠在网页填写IPv6地址得到这些能力。

池入口例如 `https://pool.example:18443`，只允许 HTTPS（加密HTTP）源地址，不包含路径、查询参数或用户名。管理令牌至少32字符；管理接口请求携带 `Authorization: Bearer <池管理令牌>`。

申请：`POST /v1/leases`（申请一次性出口租约），成功响应直接返回对象，不套业务数据包装：

```json
{
  "id": "0123456789abcdef0123456789abcdef",
  "proxy_url": "https://0123456789abcdef0123456789abcdef:ONE_TIME_PASSWORD@pool.example:18443",
  "ipv6": "2001:db8::1234"
}
```

示例IPv6是文档专用地址，不能用于真实出站。租约ID必须是32个十六进制字符；代理地址必须为与池入口相同主机和端口的 HTTPS 地址，用户名等于租约ID。代理需要支持 HTTP CONNECT（建立到目标服务器的隧道）及租约凭据认证，使这条隧道实际从租用IPv6出站。

释放：`DELETE /v1/leases/{id}`，返回成功状态即可。客户端无论探测成功与否都调用；若释放失败，池自身也必须按租期回收。

池服务应预先批量准备地址，原子分配且不重复租出；已使用地址退役，补足待用库存。生成随机IPv6字符串并不等于可以上网，服务器须具备对应前缀路由、地址绑定和必要的邻居发现支持。池管理令牌与每个临时代理的认证凭据分离，避免用长期管理密钥当所有代理密码。

自签名 CA（验证池身份的信任证书）可由管理员在网页粘贴或上传，后端从内存载入。不能用关闭TLS验证来解决证书问题。当前IPv6客户端检查租约返回的地址格式并通过所给代理发送，但**不采用购买IPv4模式的同连接地址回显流程**，其真实出口可靠性还依赖池服务自身正确绑定与测试。

## 9. 网页配置、数据字段和管理员接口

账号扩展字段：

```json
{
  "codex_turn_state_auto_enabled": true,
  "codex_turn_state_profile": "team",
  "codex_turn_state_source": "purchased"
}
```

它们分别表示自动采集开关、规则和来源。另选值为 `pro`、`ipv6_pool`。明确保存账号设置后，手动采集才使用这些新选择；未保存的表单不是后端真实配置。

全局设置字段：

| 字段 | 含义 |
| --- | --- |
| `revision` | 读回时获得的配置版本，保存时回传，用于检测过期表单 |
| `purchased_enabled` | 是否启用购买IPv4服务 |
| `proxy_host`、`proxy_username`、`proxy_password` | 购买代理地址、用户名模板与密码 |
| `countries` | 逗号分隔国家代码 |
| `proxy_upstream`、`clear_proxy_upstream` | 可选前置SOCKS5地址，以及显式清除标志 |
| `ipv6_enabled` | 是否启用独立IPv6池 |
| `pool_url`、`pool_token`、`pool_ca` | 池入口、管理令牌、CA证书文本 |
| `attempts`、`concurrency` | 每轮尝试上限、单实例并发上限 |
| `proxy_password_configured`、`proxy_upstream_configured`、`pool_token_configured` | 回读时只说明相应凭据是否存在，不返回原秘密 |

密码和池令牌空白表示保留；前置代理空白也表示保留，需单独勾选清除。配置整体加密写数据库，不放浏览器本地存储，不写账号导出数据，不把请求正文落入审计日志。当前加密采用 AES-GCM（带完整性校验的对称加密），独立用途的密钥由既有 `JWT_SECRET`（服务登录签名密钥）派生；所有实例须一致且持久保留，改动会导致旧配置无法解密。

网页保存先校验并构造新采集器，数据库写入成功才发布；校验或保存失败保留旧运行配置。当前实例保存后应用，其他实例正常情况下约15秒同步。旧环境变量配置只在数据库从未保存时作为兼容后备。

所有下面的路由都在现有管理员认证范围内，不开放给普通用户。响应沿用你分支的标准数据包装：

| 方法与路径 | 含义 |
| --- | --- |
| `GET /api/v1/admin/accounts/{id}/turn-state` | 已保存开关、服务配置可用性、服务器时间及模型状态 |
| 同路径加 `?history=1` | 同时返回检测记录 |
| `POST /api/v1/admin/accounts/{id}/turn-state/acquire` | 提交 `{"model":"gpt-6-astra"}` 开始或复用后台任务 |
| `GET /api/v1/admin/accounts/turn-state/settings` | 读取脱敏后的全局配置 |
| `PUT /api/v1/admin/accounts/turn-state/settings` | 保存完整配置，校验并应用 |

手动接口返回 `queued: true`（任务已受理），不表示已获取合格状态。配置“可用”也只是初始化校验通过，不代表代理网络实测已通。历史只显示国家、出口、模型、规则、来源、状态码、长度、耗时和失败摘要，不返回账号令牌、代理密码或完整状态值。

## 10. 朋友改造时的验收顺序

1. 不配置采集服务或关闭账号开关时，原业务转发正常。
2. 在网页配置购买代理，保存后状态更新；再次打开密码不回显，空白保存仍能保留；重启后配置存在。
3. 未发业务请求的新账号，点击手动按钮能真正发起最小探测；不是等待已有缓存，也不是完整问答。
4. 连续3次356或失败切换国家；一次获得合格值即保存；401/403/429终止本轮。
5. 同账号、同模型重复点击不叠加任务；并发满时队列最终执行，已有新鲜缓存的手动刷新也实际采集。
6. 成功后检查最终送出的字段与该账号模型缓存一致；普通、流式、换账号重试和长连接路径都覆盖。不要只检查中间构造出的请求。
7. 两个账号同模型、一个账号两个模型、身份更换、规则切换均不串用；关闭或切换期间完成的旧任务不发布。
8. 签发满30分钟刷新、失败保留未过期旧值、满60分钟停止注入；测试时可使用受控时间或模拟缓存，不必真的等1小时。
9. 状态页倒计时以服务器时间校正；历史无凭据；认证错误与网络失败可区分。
10. 最后以自己的授权账号作少量真实请求测试，另用答案已核实的评测题判断质量，不把字段长度当作质量结论。

独立移植到这里即可覆盖当前功能，不必先获得参考项目。具体分支的账号类型、模型映射、授权刷新、最终请求和长连接结构需要按其现有代码适配。
