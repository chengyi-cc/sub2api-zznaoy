# Excel / BPS 请求通道

移植来源：截至 2026-09-25 核对的 [`ranxi2001/sub2api production`](https://github.com/ranxi2001/sub2api/commit/055a1cd1470b3b866d04aad8d1514bd34cac73ab)，固定版本 `055a1cd1470b3b866d04aad8d1514bd34cac73ab`。包含最新发布 v2.8.11，以及发布后的结构化输出和缓存创建计费选项。仅移植 Excel / BPS 相关功能与修复。协议来源说明保留在 `backend/internal/service/basispoints/NOTICE.md`。

这里的 Excel 是请求通道，不是上传、下载或操作表格的功能。BPS（Basispoints，上游 Excel 插件使用的协议）通过 `https://bps.openai.com/basispoints/api/responses` 接收模型请求。本项目负责把 Responses（统一模型响应接口）的消息、工具与输出转换成对应格式，再还原给客户端。

## 如何开启

1. 更新包含本次提交的程序；无需额外数据库迁移、额外进程或新凭据。
2. 在“账号管理”编辑一个 **OpenAI OAuth（通过 ChatGPT 登录授权）账号**，在顶部模板下方找到放大的“Excel / BPS 协议”开关，打开并保存。默认关闭，逐账号生效。
3. 客户端继续使用本项目原有服务地址、密钥和 HTTP `/v1/responses`；无需改成 BPS 的上游地址。保存后新建 Codex 会话，使用账号实际有权限的模型。
4. 如果要确保请求只走 BPS，可把开启的账号放进独立分组，并让客户端密钥绑定该分组。混合分组仍按原调度规则选择账号，因此未开启的账号继续使用原路径。
5. 编辑账号关闭开关并保存，即恢复原路径；切换后也建议新建会话。

开关不对 API Key（上游接口密钥）、Setup Token（手动接入令牌）、影子账号、Agent Identity（代理身份凭据）及个人访问令牌账号显示或生效。它不修改账号凭据、停用状态、调度开关、分组、并发和代理，也不会覆盖账号模板里的现有设置。

## 功能

- 支持 HTTP `/v1/responses`、`/v1/responses/compact`（会话压缩接口），以及流式和非流式返回。流式文字边生成边返回。
- 支持 function（结构化参数工具）、custom（原始文本工具）、namespace（工具分组）和 Lite additional_tools（会话内补充工具声明）。保留工具调用编号、参数、大整数和原始补丁/脚本内容。
- 转换上游 `run_officejs`（Excel 原生工具承载格式）及已声明工具的直接调用。这里只转换数据，不在服务器执行客户端命令或 Office 脚本；未知工具、类型不匹配和不完整调用不会提前交给客户端执行。
- 工具等完整响应验证通过后再发出；工具结果按调用编号匹配，原始记录按账号、客户端密钥和线程隔离。子会话可独立发送请求，仍受账号并发及上游能力限制。
- 复用账号登录凭据及刷新逻辑、代理、模型映射、用量记录和现有调度。开启后优先走 HTTP/SSE（持续推送响应的连接），不走 WebSocket（双向长连接）或原自动透传；关闭后恢复原先保存的连接设置。
- 我们已有的账号连接测试、糖果检测及其定时监测也跟随该开关，检测的是实际选中的通道。21/29 判定、计数及不可用账号跳过规则不变。
- 支持 JSON 对象及 JSON Schema（规定输出字段和类型的规则）格式：通过提示要求生成 JSON，完整返回后在本地验证，通过才发送最终正文。这不是上游强制生成保证，验证失败会明确报错；不读取外部规则网址或文件。
- 可选“创建缓存按普通输入计费”，默认关闭。仅影响本系统计费和用量分类，缓存读取不变，原始上游用量不变。关闭 Excel / BPS 开关时同时移除此计费选项。
- 修复工具输出编号兼容性、重复错误响应和压缩请求的错误事件；运维错误详情按日志设置保存，并隐藏账号令牌等敏感信息。

## 使用边界

- 模型权限由上游决定，开启不保证解锁任何模型，也不自动换模型。`max`、`ultra`（推理强度档位）转成 `xhigh`；`none`、`minimal` 转成 `low`，用量保留请求档位及实际档位。
- 图片理解支持上游可访问的 HTTPS 图片链接；base64（请求中内嵌图片数据）自动转成本机临时链接，无需对象存储。文件编号和本地路径仍不支持，也不提供图片生成通道。
- 托管工具（上游执行的网页搜索、文件搜索、代码解释器等）不能作为客户端工具执行。自动模式会省略已知托管工具并向模型说明限制；未知工具和强制指定工具会明确报错。仅靠 `previous_response_id`（旧响应编号）续接不支持；需传完整历史。
- 工具回放缓存只在当前服务进程内，最多 1024 项、16 MiB。完整调用历史可按新版规则重建；只有工具结果且缺少对应缓存时会要求新建会话。重启、多实例切换或淘汰可能导致这种情况。没有线程/会话标识时不共享回放缓存，只接受可完整重建的历史。
- 请求失败不会静默切换到另一条协议或重复执行工具请求；流中断不记作账号恢复成功。正常调度仍要求账号可用，开关不会恢复停用账号。

## 验证与排查

### 客户直接上传图片

与异步生图任务一样，图片保存在部署服务器本地数据目录，**无需配置或启用「备份 → 图片对象存储」**。使用 Excel 通道的客户仍按原来方式粘贴或上传图片，服务自动转换，再由上游通过本站 HTTPS（加密网页连接）地址取图。不会将图片另存到第三方存储服务。

- 同一客户端密钥、同一会话、同一图片使用固定链接；更换上游调度账号不会换链接。链接使用 HMAC（服务器密钥生成的防猜测标识），不同用户密钥/会话相互隔离，不公开图片内容摘要。服务端签名密钥保持不变时，重启及过期清理后重新提交原图也能恢复相同链接。
- **5 分钟是可续期的有效期**：合法模型请求每次携带原图时续期 5 分钟，过期时间只存服务器文件元数据，不放进链接。停止提交原图 5 分钟后，链接立即返回 404；访问/下载图片不能续期。重新提交原图会重新开放这个链接，旧链接持有者在重新开放期间也能访问，因此应将链接当作临时凭证保密。
- 默认目录为 `data/jobs/images-excel-inputs`；如设置了 `gateway.image_jobs.root_dir`（异步图片任务目录），则使用该路径加 `-excel-inputs` 的独立目录，避免混入任务清理。沿用 `pricing.data_dir`（数据目录）默认路径，容器请持久化数据目录。临时图片有独立磁盘限额，复用 `gateway.image_jobs.max_total_disk_mb` 数值，缺省 1 GiB，最多 10000 张；满额只清理过期文件，不驱逐仍有效的会话图片。
- 每分钟及启动时清理过期文件，通常在停止提交后 5～6 分钟删除；访问是否过期始终实时检查，不依赖清理任务是否及时运行。
- 链接域名优先取站点设置的 API 基础地址、前端地址，再取配置文件前端地址；均未设置时取当前请求的主机地址，使用 HTTPS，不采信任意转发主机头。已有地址以 `/v1` 结尾会自动去掉这一后缀。站点反向代理需将 `/v1/excel-images` 的 GET/HEAD（取图/查询大小）请求转发到程序；该端点依靠临时链接凭证校验，不要求客户端密钥。不能配置公共缓存或记录完整取图查询参数。
- 本机取图返回 `no-store`（禁止网页/代理缓存），它与模型的提示缓存是两回事。当前按单实例本地磁盘设计；多实例需保证模型请求及取图落在同一实例，不能仅靠共享目录获得跨进程并发保护。本站公网域名必须能被上游访问。
- 支持 PNG、JPEG、GIF、WebP；每张最多 20 MiB、4000 万像素，每个请求最多 16 张内嵌图片，解码后总计不超过 32 MiB。仍受站点请求体大小限制。
- 校验整条协议请求后才落盘，重复图片只存一份；失败时撤销本次新建文件，并明确报错，不切换普通通道。
- 原始客户历史不会被改写。客户端继续发送原图数据，服务端在上游请求中替换 `image_url`（图片地址字段）；没有新增客户端字段。仅保存过期外部链接而不提供原图，无法自动恢复。
- 本地路径或 `file_id`（文件编号）不能当作图片数据上传。普通通道和已有 HTTPS 图片链接保留原有行为。

自动化测试覆盖完整上游请求在续期前后逐字节一致、过期与原图恢复、用户/会话隔离、重启续用与启动清理、32 路并发读写及清理、磁盘限额、GET/HEAD 取图与过期拒绝、路径穿越拒绝、凭证隐藏、格式校验及普通通道兼容性。实际部署的公网取图仍需部署后验证，本地自动化测试不能证明服务器反向代理及外网连通性。

### 图片与长对话缓存实测

2026-09-25 使用同一真实账号和 `gpt-6-astra`，以公开水果图片加长文本做 8 次请求。固定会话缓存标识及协议元数据，只在实际发出的图片 URL 中切换查询参数 A → A → B → B → A → A：首轮输入 30045、缓存读取 22132；其余五轮均读取 29988。随后追加两轮对话，输入分别 30064、30083，缓存读取分别 29860、29988，均正确识别猕猴桃。

这次测试中，同图变更链接参数**没有观察到缓存丢失**，说明不能简单认定“字段变化必然全部失去缓存”。测试仅覆盖该上游、该图片及查询参数变化，不保证所有签名域名/路径的处理相同。固定链接仍能避免本项目主动引入图片地址变化；缓存能否命中还取决于模型、历史内容、会话标识及上游缓存策略。上述公开图片测试不等同于已验证用户服务器的本地取图地址。

代码测试覆盖协议转换、直接调用恢复、原始工具输入、会话历史、账号/密钥/线程隔离、取消请求、未完整结束的响应、压缩与大整数、开关保存/关闭、非授权类型限制以及糖果检测走 BPS。

2026-09-25 使用用户指定账号和 `gpt-6-astra` 实测：三轮交替糖果测试中普通通道均返回 29、Excel 均返回 21；公开图片链接识别、重复长文本的缓存用量均正常；最高测试到 32 路同时请求，均完成且返回 21。这是单账号、单时间段的测试下限，不代表绝对并发上限或长期稳定性保证。

模型权限错误应检查所选模型和账号；提示原工具记录不可用时新建会话。用量记录的上游路径为 `/basispoints/api/responses`。
