# Excel / BPS 请求通道

移植来源：截至 2026-09-25 核对的 [`ranxi2001/sub2api production`](https://github.com/ranxi2001/sub2api/commit/055a1cd1470b3b866d04aad8d1514bd34cac73ab)，固定版本 `055a1cd1470b3b866d04aad8d1514bd34cac73ab`。包含最新发布 v2.8.11，以及发布后的结构化输出和缓存创建计费选项。仅移植 Excel / BPS 相关功能与修复。协议来源说明保留在 `backend/internal/service/basispoints/NOTICE.md`。

这里的 Excel 是请求通道，不是上传、下载或操作表格的功能。BPS（Basispoints，上游 Excel 插件使用的协议）通过 `https://bps.openai.com/basispoints/api/responses` 接收模型请求。本项目负责把 Responses（统一模型响应接口）的消息、工具与输出转换成对应格式，再还原给客户端。

## 如何开启

1. 更新包含本次提交的程序；无需额外数据库迁移、额外进程或新凭据。
2. 在“账号管理”编辑一个 **OpenAI OAuth（通过 ChatGPT 登录授权）账号**，在顶部模板下方找到放大的“Excel / BPS 协议”开关，打开后勾选需要使用 Excel 通道的模型并保存。默认关闭，逐账号生效。
3. 客户端继续使用本项目原有服务地址、密钥和 HTTP `/v1/responses`；无需改成 BPS 的上游地址。保存后新建 Codex 会话，使用账号实际有权限的模型。
4. 如果要确保请求只走 BPS，可把开启且勾选目标模型的账号放进独立分组，并让客户端密钥绑定该分组。混合分组仍按原调度规则选择账号，因此未开启的账号继续使用原路径。
5. 编辑账号关闭开关并保存，即恢复原路径；切换后也建议新建会话。

开关不对 API Key（上游接口密钥）、Setup Token（手动接入令牌）、影子账号、Agent Identity（代理身份凭据）及个人访问令牌账号显示或生效。它不修改账号凭据、停用状态、调度开关、分组、并发和代理，也不会覆盖账号模板里的现有设置。

## 按模型选择通道

“使用 Excel 通道的模型”位于账号编辑页顶部协议开关下方，可搜索、多选、移除或添加自定义模型。默认勾选 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`。`gpt-6-sol` 等其他模型保留为可选项，默认未勾选并走原流程。清空选择表示所有模型走原流程。

配置保存在 `extra.openai_excel_bps_models`（逐账号模型名单）；此前仅开启协议的账号，在缺少此字段时自动使用上述三个默认模型，无需迁移。显式空列表不会恢复默认选择。名单按账号正常模型映射后的实际名称精确匹配，不使用前缀或通配符。

普通通道保留原连接模式和计费逻辑；“创建缓存按普通输入计费”仅作用于实际发送到 Excel 的请求。勾选模型请求失败会明确报错，不自动重发到其他通道。普通 WebSocket（双向长连接）会话内切换到勾选模型时，需新建 HTTP 请求，不能在已有连接里静默绕过选择。

2026-09-25 使用用户指定账号实测：上述三个默认模型的 Excel 请求均成功；`gpt-6-sol`、`gpt-6-luna`、`gpt-5.4`、`gpt-5.5` 的 Excel 请求均返回 403（上游拒绝）。修改后复测确认三个默认模型仍经 Excel 成功，未勾选 `gpt-6-sol` 实际进入普通通道，但上游返回 400，提示该模型不支持此 ChatGPT 账号；显式勾选后确实进入 Excel，仍被上游以 403 拒绝。这是单账号实测，不代表所有账号和时段的模型权限。

## 功能

- 支持 HTTP `/v1/responses`、`/v1/responses/compact`（会话压缩接口），以及流式和非流式返回。流式文字边生成边返回。
- 支持 function（结构化参数工具）、custom（原始文本工具）、namespace（工具分组）和 Lite additional_tools（会话内补充工具声明）。保留工具调用编号、参数、大整数和原始补丁/脚本内容。
- 转换上游 `run_officejs`（Excel 原生工具承载格式）及已声明工具的直接调用。这里只转换数据，不在服务器执行客户端命令或 Office 脚本；未知工具、类型不匹配和不完整调用不会提前交给客户端执行。
- 工具等完整响应验证通过后再发出；工具结果按调用编号匹配，原始记录按账号、客户端密钥和线程隔离。子会话可独立发送请求，仍受账号并发及上游能力限制。
- 复用账号登录凭据及刷新逻辑、代理、模型映射、用量记录和现有调度。仅勾选模型走 HTTP/SSE（持续推送响应的连接），不走 WebSocket（双向长连接）或原自动透传；未勾选模型以及关闭开关后均使用原先保存的连接设置。
- 我们已有的账号连接测试、糖果检测及其定时监测也跟随该开关和模型选择，检测的是实际选中的通道。21/29 判定、计数及不可用账号跳过规则不变。
- 支持 JSON 对象及 JSON Schema（规定输出字段和类型的规则）格式：通过提示要求生成 JSON，完整返回后在本地验证，通过才发送最终正文。这不是上游强制生成保证，验证失败会明确报错；不读取外部规则网址或文件。
- 可选“创建缓存按普通输入计费”，默认关闭。仅影响本系统计费和用量分类，缓存读取不变，原始上游用量不变。关闭 Excel / BPS 开关时同时移除此计费选项。
- 修复工具输出编号兼容性、重复错误响应和压缩请求的错误事件；运维错误详情按日志设置保存，并隐藏账号令牌等敏感信息。

## 使用边界

- 模型权限由上游决定，开启不保证解锁任何模型，也不自动换模型。`max`、`ultra`（推理强度档位）转成 `xhigh`；`none`、`minimal` 转成 `low`，用量保留请求档位及实际档位。
- 图片理解支持上游可访问的 HTTPS 图片链接；base64（请求中内嵌图片数据）自动上传到 OpenAI 附件接口并转成官方文件编号。无需对象存储或本站公网取图。客户端直接提供的文件编号及本地路径仍不支持，也不提供图片生成通道。
- 托管工具（上游执行的网页搜索、文件搜索、代码解释器等）不能作为客户端工具执行。自动模式会省略已知托管工具并向模型说明限制；未知工具和强制指定工具会明确报错。仅靠 `previous_response_id`（旧响应编号）续接不支持；需传完整历史。
- 工具回放缓存只在当前服务进程内，最多 1024 项、16 MiB。完整调用历史可按新版规则重建；只有工具结果且缺少对应缓存时会要求新建会话。重启、多实例切换或淘汰可能导致这种情况。没有线程/会话标识时不共享回放缓存，只接受可完整重建的历史。
- 请求失败不会静默切换到另一条协议或重复执行工具请求；流中断不记作账号恢复成功。正常调度仍要求账号可用，开关不会恢复停用账号。

## 验证与排查

### 客户直接上传图片

更新后，使用 Excel 通道的客户继续按原来方式粘贴或上传图片，无需新设置。网关使用所选账号的登录凭证和代理，把图片发送到 `https://bps.openai.com/basispoints/api/attachments`（OpenAI 的 Excel 附件接口），取得 `openai_file_id`（官方文件编号），再在模型请求中用 `file_id` 引用图片。

实现参考了 [excel-codex-bridge 的附件协议](https://github.com/Kaixxrua/excel-codex-bridge/blob/8acc2ccb09840cfc202ee1a718e70aab2ec7e56d/src/excel_codex_bridge/images.py)。本项目实测已有 OpenAI 直接登录授权账号也可以上传和识图；无需读取本机 Excel 登录态。

- 用户消息和工具输出里的内嵌图片均自动转换；已有 HTTPS 图片链接原样转发。客户端继续发送原图，不需要获得或维护官方文件编号。
- 图片发送到 OpenAI，此上传流程不再写本地图片文件，不依赖本站公网域名、临时链接、隧道或对象存储。
- 同一个客户端密钥、同一个上游账号、相同图片内容复用文件编号；账号、客户密钥或上游账号身份变化时分别缓存。同图并发请求共享一次上传，不跨客户共享文件编号。刷新登录令牌不会单独导致重新上传。
- 内存最多缓存 1024 个文件编号，优先淘汰最近最少使用的记录；缓存不保存图片或登录令牌。重启、缓存淘汰或切换上游账号后，重新提交原图会再次上传。单实例最多同时执行 32 个不同图片的上传，同图等待者共用结果；上传超时 120 秒，也响应请求取消。
- 模型协议和图片格式先校验，再上传；支持 PNG、JPEG、GIF、WebP，每张最多 20 MiB、4000 万像素，每次最多 16 张、解码后合计最多 32 MiB。上传不能重定向到其他地址，使用与模型请求相同的账号、代理和传输层。
- 上传失败、认证失败、文件编号缺失或非法时明确报错；不省略图片继续回答，不切换普通通道，不自动重放模型请求。上游明确报告文件不存在、编号无效或过期时，删除对应的本地编号缓存，下一次客户端重试会重新上传。
- 会话/轮次标识仍由稳定图片内容占位符计算，不因上传返回的编号变化而重算。缓存命中还受上游账号、历史内容及上游策略影响，不作绝对命中保证。
- **图片改由 OpenAI 保存，不能保证上传后 5 分钟删除。** 此实现没有调用已验证的官方删除接口，也不将内存缓存淘汰当成官方文件删除。
- 旧 `/v1/excel-images`（本站临时取图端点）已移除，旧链接无法再取图。仅保留旧本地临时文件的过期清理：启动时及每分钟清理超过 5 分钟的旧文件，不新建目录、不写新图片，也不触碰异步生图任务结果。已有生成图片对象存储功能不受此变更影响。

### 实测与自动验证

2026-09-25 使用用户指定账号及 `gpt-6-astra` 实测：官方附件上传返回 200 并提供文件编号；随后 4 次通过编号识图均完成，正确识别猕猴桃、橙子与紫甘蓝。重复长文本请求输入 28620，缓存读取 28580（约 99.86%）；追加对话后输入 28647，缓存读取 28452。

随后通过修改后的实际网关发送 5 次内嵌图片请求，共发生 **1 次官方附件上传**，全部正确识图。前三轮重复请求输入 30045、缓存读取 29988；追加两轮历史后缓存读取分别为 22132 和 29988，可见上游命中量会波动。这是当前账号和时段的实测结果，不保证所有账号均具备同样权限。

自动化测试覆盖完整请求体复用、32 路同图并发去重、客户/账号隔离、失败不发送模型请求、上传格式及凭证、非法响应、缓存上限与失效处理、普通通道兼容和旧本地文件清理。

同日此前实测：三轮交替糖果测试中普通通道均返回 29、Excel 均返回 21；最高测试到 32 路同时请求，均完成且返回 21。这是单账号、单时间段的测试下限，不代表绝对并发上限或长期稳定性保证。

模型权限错误应检查所选模型和账号；提示原工具记录不可用时新建会话。用量记录的上游路径为 `/basispoints/api/responses`。
