# Excel / BPS 请求通道

当前兼容性审计基线（2026-09-26）：ranxi2001/sub2api `production` 的 `f671a8d30c34706d8526accadf6a6ad5f40f855e`（相较 `594cdf0d6` 仅新增使用教程，无功能代码变化）（最新发布 v2.8.14），以及 Kaixxrua/excel-codex-bridge `main` 的 `8a277dfcdbb647d2ef4d714e31b6a98260a63a79`（最新发布 v0.5.1）。初次移植基于 ranxi `055a1cd14` / v2.8.11；后续按功能移植，不合并其他项目整套数据库和部署。来源见 `backend/internal/service/basispoints/NOTICE.md`，逐项取舍见下方对照表。

这里的 Excel 是请求通道，不是上传、下载或操作表格的功能。BPS（Basispoints，上游 Excel 插件使用的协议）通过 `https://bps.openai.com/basispoints/api/responses` 接收模型请求。本项目负责把 Responses（统一模型响应接口）的消息、工具与输出转换成对应格式，再还原给客户端。

## 如何开启

1. 更新包含本次提交的程序；无需额外数据库迁移、额外进程或新凭据。
2. 在“账号管理”编辑一个 **OpenAI OAuth（通过 ChatGPT 登录授权）账号**，在顶部模板下方找到放大的“Excel / BPS 协议”开关，打开后勾选需要使用 Excel 通道的模型并保存。默认关闭，逐账号生效。
3. 客户端继续使用本项目原有服务地址、密钥和 HTTP `/v1/responses`；无需改成 BPS 的上游地址。保存后新建 Codex 会话，使用账号实际有权限的模型。
4. 如果要让支持 Excel 的请求选到已开启账号，可把开启且勾选目标模型的账号放进独立分组，并让客户端密钥绑定该分组。混合分组仍按原调度规则选择账号，因此未开启的账号继续使用原路径。
5. 编辑账号关闭开关并保存，即恢复原路径；切换后也建议新建会话。

开关不对 API Key（上游接口密钥）、Setup Token（手动接入令牌）、影子账号、Agent Identity（代理身份凭据）及个人访问令牌账号显示或生效。它不修改账号凭据、停用状态、调度开关、分组、并发和代理，也不会覆盖账号模板里的现有设置。

## 按模型选择通道

“使用 Excel 通道的模型”位于账号编辑页顶部协议开关下方，可搜索、多选、移除或添加自定义模型。默认勾选 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`。`gpt-6-sol` 等其他模型保留为可选项，默认未勾选并走原流程。清空选择表示所有模型走原流程。

配置保存在 `extra.openai_excel_bps_models`（逐账号模型名单）；此前仅开启协议的账号，在缺少此字段时自动使用上述三个默认模型，无需迁移。显式空列表不会恢复默认选择。名单按账号正常模型映射后的实际名称精确匹配，不使用前缀或通配符。

普通通道保留原连接模式和计费逻辑；“创建缓存按普通输入计费”仅作用于实际发送到 Excel 的请求。勾选模型请求失败会明确报错，不自动重发到其他通道。普通 WebSocket（双向长连接）会话内切换到勾选模型时，需新建 HTTP 请求，不能在已有连接里静默绕过选择。

2026-09-25 使用用户指定账号实测：上述三个默认模型的 Excel 请求均成功；`gpt-6-sol`、`gpt-6-luna`、`gpt-5.4`、`gpt-5.5` 的 Excel 请求均返回 403（上游拒绝）。修改后复测确认三个默认模型仍经 Excel 成功，未勾选 `gpt-6-sol` 实际进入普通通道，但上游返回 400，提示该模型不支持此 ChatGPT 账号；显式勾选后确实进入 Excel，仍被上游以 403 拒绝。这是单账号实测，不代表所有账号和时段的模型权限。

## 2026-09-26：嵌套工具转换修复

再次核对参考项目当前分支：ranxi2001/sub2api 的 production 为 f671a8d30，Kaixxrua/excel-codex-bridge 的 main 为 8a277df。两者都没有处理这次复现的嵌套工具调用：前者拒绝不在目录中的名字；后者跳过无法转换的调用。跳过不能证明工具已经执行。

受控复现使用原问题会话的 compaction（加密压缩历史），当前目录只声明 functions.exec（运行工具编排脚本的入口）。上游仍返回 exec_command（该入口内部的命令执行工具）作为外层工具名，从而触发“tool outside the client's catalog”。之前仅兼容 functions. 名称前缀的修复无法覆盖这层关系。

本次在转换器补齐缺少的一层：只识别当前 exec 说明中明确的 tools 类型声明，把误放到外层的单个函数调用转换成现有 exec 自定义调用。参数经过 JSON（结构化数据格式）编码后作为数据传入，不把参数拼成可执行语句。网关不执行脚本；调用仍由客户端处理。精确声明的普通工具优先；未声明、歧义、混合输入、无效参数及未授权的名称仍报错。同一响应仍全部验证后派发，不丢弃错误工具伪造成功。

验证包括：修复前相同错误的回归复现、修复后真实上游返回转换、客户端只读输出、实际结果回传和最终文字完成；另覆盖普通/自定义工具、命名空间、并行终态、重启后历史重建、未知工具拒绝及竞态测试。真实探测使用 low（低推理强度），工具响应约 5.6 秒，结果回传约 3.8 秒，仅表示该次探测，不代表原长会话的固定响应时间。此前分钟级等待还包含上游生成及客户端失败重试，不能算成本地 ID 转换时间。

原固定消息编号算法、缓存键和回放隔离方式不变；新增说明放在稳定前缀中，同样的输入重复转换结果相同，不在每轮历史末尾追加提醒。发布后带 exec 目录的提示前缀会一次性改变，因此不能承诺升级当次零缓存影响；后续前缀保持稳定。

### 同日后续：第二轮延迟工具

原会话更新后，第一条命令已执行成功（退出码 0），但结果回传后的下一次调用仍报同一类目录错误。受控续测捕获 mcp__node_repl.js（Node.js 脚本执行工具），而客户端实际通过 exec 暴露 mcp__node_repl__js（可在编排脚本中调用的名称）。这类延迟工具的完整说明还可能未出现在初始目录中。单次命令与回传测试没有覆盖这个后续路径。

补充修复只规范 MCP（外部工具接口）的 server.method 名称；当 exec 明确声明 ALL_TOOLS（当前实际可用工具目录）能力时，在客户端先核对唯一、可调用的精确条目，再执行。工具缺失、重复或不可调用时返回 tool_not_available（未执行任何工具），让模型查找有效入口，而不是把恢复不了的名字变成整段流失败并反复重试。不把其它任意名称或 namespace（工具分组）尾部猜成可用工具；精确声明的普通工具仍优先。

补充验证覆盖“命令调用→回传→Node 工具→再次回传”的连续历史、真实捕获数据转换、真实 Node 调用，以及可用、缺失、重复、不可调用、无运行时目录五个分支。参数与调用编号保持稳定。该记录不等于宣称所有长会话与所有延迟工具均已线上验证。

此次未直接引入参考项目额外请求模型纠正封装的机制：它会改变重试、耗时和用量累计，需要另外验证纠正前后业务操作与参数不变。现有严格校验仍会拒绝无法确定的工具调用，不静默执行或丢弃它们。新增兼容修复须部署服务器后才作用于客户请求。

### 加密推理历史的受限恢复（2026-09-26）

线上出现 HTTP 400 / `invalid_encrypted_content`（上游无法验证加密历史）时，BPS 分支原先直接包装成通用错误，未进入普通 Responses 分支已有的恢复逻辑。现在增加独立、受限的恢复，不复用会删除 compaction（压缩后历史）的宽泛清洗：

- 仅处理 HTTP 400 且错误代码精确匹配的响应；上游必须用字段路径或足够长的密文首尾标记，唯一指向某份 reasoning（可选推理历史）。无法确定、多个不同密文匹配、错误体损坏时均不重发。
- 完整保留用户/助手消息、工具调用、工具结果、图片及其他有效密文。若携带 compaction、compaction_summary、item_reference 或其他类型的加密消息，则不删除任何内容。恢复仅省略已经定位的失效推理项，不能保留该项内部不可解密的推理信息。
- 在相同账号上最多重发一次；不因网络异常、其它错误、流式输出失败再次重发，也不切换账号或端点。只有最终得到 response.completed（响应完整结束）后，才记录已恢复密文的摘要。
- 摘要记录按上游账号编号、真实账号身份、API Key（调用密钥）、线程与模型隔离，使用现有带过期时间和容量上限的内存状态。后续同范围请求只过滤成功恢复过的推理项，不会每轮先失败一次；进程重启/过期后最多重新经历一次拒绝及恢复。
- 正常请求不多发模型请求，也不改变缓存前缀。首次恢复会改变失败历史对应的前缀，后续同内容保持稳定；不能承诺故障恢复对缓存命中率零影响。
- 无法恢复时向客户端保留 `invalid_encrypted_content`，附固定提示；运维记录追加加密内容类别计数及是否已尝试恢复，不记录完整密文、用户消息或工具参数。嵌套 `encrypted_content` 内容块的本地拒绝现在能显示该固定类型标签，不再只显示 unknown。

验证涵盖流式/非流式恢复、仅移除匹配项、工具参数与大整数不变、重发上限、失败不写摘要、跨账号/身份/密钥/线程/模型隔离以及压缩历史不误删。真实上游使用独立合成历史复现相同的加密错误，保留明文消息并移除测试坏推理后返回成功且正确记住测试词。该结果验证恢复机制，不证明线上错误 #1930080 的实际坏内容一定属于可恢复的 reasoning；故障请求未存原文，仍需更新服务后结合分类诊断确认。此前 #1930084 的 unknown 内容同样不能据此宣称已经兼容。

## 功能

### 工具封装自动纠正与错误存档（2026-09-26）

- 当模型已经完整返回、但 `run_officejs`（上游用来承载客户端工具的函数）封装不符合当前客户端声明时，最多追加两轮同账号、同模型的纠正请求，每轮最多 45 秒。用户关闭连接时同时取消纠正。客户端工具尚未派发，所以不会先执行一次再重试一次。
- 纠正只调整传输封装。已有合法调用的目标与参数必须一致；原始脚本、补丁或原始文本逐字保留；可识别封装的参数和函数代码的额外元数据也必须一致。未知目标、改变操作、重复编号、不完整响应或无法确认的数据仍会失败，不能承诺所有错误自动消失。
- `parallel_tool_calls:false`（客户端规定本次最多返回一个工具）不会被改成允许并行。错误批次可以纠正为原批次中完全相同的第一个操作，其余操作没有执行，交给模型收到真实结果后的下一轮再判断；本服务不偷偷执行整批或创建后台待执行队列。
- 客户端没有可匹配的 `update_plan`（更新计划的工具）时，可让模型把计划改为一条普通文字回复。它只是计划文字，不表示工具已执行，也不保证本轮会继续实际工作。
- 只有出错时才增加模型请求和等待，并合并这些轮次的用量。正常请求的提示前缀、缓存编号、工具目录、账号调度保持原逻辑；纠正请求追加错误反馈，会有额外输入与费用，缓存命中由上游决定。
- `Failed to read request body`（服务未能完整读入请求正文）发生在模型调用之前，模型无法补回丢失的上传字节。本次补上固定原因分类，例如 `truncated_body`（正文中断）、`read_timeout`（读取超时）、`decode_content_encoding`（压缩正文解码失败），不把它伪装成已修复的模型错误。旧记录没有原始原因或正文时不能追溯还原。

#### 错误样本保存和下载

`ops.error_archive`（错误请求临时存档）默认启用，依赖运维监控开关；默认保存 72 小时、每个请求最多截取 4 MiB、目录总量最多 512 MiB、最多 4096 个样本，容量不足优先删除最旧样本。保留时间可配置 1–720 小时。启动时和每 5 分钟清理；下载时立即拒绝已过期样本。崩溃残留的临时加密文件到期后也会清理。

配置示例见 `deploy/config.example.yaml`。默认路径为 `DATA_DIR/error-archives`（服务数据目录内的子目录），未设置数据目录时使用 `./data/error-archives`。需要持久化这个目录并保留稳定的 `jwt.secret`（服务器认证签名密钥，也用于派生存档加密密钥）；密钥更换后旧存档无法解密。文件使用 `AES-GCM`（带篡改校验的加密算法），新建目录和文件按服务私有权限保存。

管理员进入“错误请求 → 详情 → 诊断载荷”，有新存档时会显示有效期、截断或读取错误提示，以及“下载调试样本”按钮。下载只返回样本，不发出原请求。接口均在现有管理员认证路由下：

- `GET /api/v1/admin/ops/error-archives/:archive_id`：下载解密后的 JSON（结构化数据文件），浏览器禁止缓存；无效、过期、淘汰或尚未写完返回 404。
- `GET /api/v1/admin/ops/error-archives/health`：查看启用状态、已写数量、队列跳过数、写入失败数、活动采集数、已分配正文缓冲字节和内存受限次数。存档仍为尽力保存，不等待空闲队列。

修正了“8 个正常长请求占满采样名额，后续错误只能留下 capacity_exhausted（采样容量不足）”的问题。每个请求始终有轻量读取观察器，正文按实际读取量申请共享内存预算（单请求采集上限的 8 倍，默认 32 MiB），不再按 8 个活动请求拒绝采样。额外的上游诊断只在发生错误时申请名额，最多 8 份同时采集；磁盘写入队列独立最多等待 8 份。达到正文内存预算时标记 capture_limited（正文采集受限），保留可用前缀、已收字节、读取失败原因和响应元信息，不能声称完整重放。写入队列也满时记录 queue_full（写入队列已满）且不生成下载编号，但数据库错误记录仍保留读取失败原因。

无样本时不再输出公元 1 年的占位过期时间。详情页兼容旧 capacity_exhausted 记录，明确提示没有生成样本；这不代表磁盘已满，旧请求正文也无法补回。前端与服务端都需要更新才能显示新的采集状态。

只对已识别客户身份的 JSON 请求采样，覆盖 Responses、Chat Completions、Messages 入口；正常成功请求丢弃，不写磁盘，未鉴权请求及 401/403 不保存。恢复成功的 BPS（Excel 上游通道）工具/历史错误也可保存，并挂到状态为 2xx 的恢复记录中；它们不计作最终失败率。

样本包括请求编号、账号/密钥的数据库编号、原始正文、压缩方式、已收字节、错误响应，以及受限的上游转换诊断。它不保存 HTTP 认证头、Cookie（登录会话凭证）或完整访问密钥。**正文可能包含用户对话、工具参数或用户写入的敏感信息，只有管理员应下载，调试结束应删除本地副本。** 数据库错误记录只保留脱敏响应和存档引用，不塞入完整对话。

`request_wire_base64`（原始网络正文的 Base64 编码）解码后还需按 `content_encoding` 解压。必须同时检查 `request_complete`、`request_truncated` 和 `read_error_kind`：大正文、客户端中途断开或未完整读取的样本只能帮助定位，不能声称可完整复现。上游诊断另有每请求 2 MiB 总预算，截断会标记；图片样本可能包含原始内嵌数据或已上传文件编号，编号失效后也不能保证重放成功。

存档在当前服务节点本地，多个实例需要到产生该错误的节点下载；没有共享的跨节点索引。本次无需数据库迁移。已有旧错误记录不会补出不存在的正文或下载按钮，需更新运行中的服务后才会产生新样本。

### 通道能力

- 支持 HTTP `/v1/responses`、`/v1/responses/compact`（会话压缩接口），以及流式和非流式返回。流式文字边生成边返回。
- 支持 function（结构化参数工具）、custom（原始文本工具）、namespace（工具分组）和 Lite additional_tools（会话内补充工具声明）。保留工具调用编号、参数、大整数和原始补丁/脚本内容。
- 转换上游 `run_officejs`（Excel 原生工具承载格式）及已声明工具的直接调用。这里只转换数据，不在服务器执行客户端命令或 Office 脚本；未知工具、类型不匹配和不完整调用不会提前交给客户端执行。
- 工具等完整响应验证通过后再发出；工具结果按调用编号匹配，原始记录按账号、客户端密钥和线程隔离。子会话可独立发送请求，仍受账号并发及上游能力限制。
- 复用账号登录凭据及刷新逻辑、代理、模型映射、用量记录和现有调度。仅勾选模型走 HTTP/SSE（持续推送响应的连接），不走 WebSocket（双向长连接）或原自动透传；未勾选模型以及关闭开关后均使用原先保存的连接设置。
- 我们已有的账号连接测试、糖果检测及其定时监测也跟随该开关和模型选择，检测的是实际选中的通道。21/29 判定、计数及不可用账号跳过规则不变。
- 支持 JSON 对象及 JSON Schema（规定输出字段和类型的规则）格式：通过提示要求生成 JSON，完整返回后在本地验证，通过才发送最终正文。这不是上游强制生成保证，验证失败会明确报错；不读取外部规则网址或文件。
- 可选“创建缓存按普通输入计费”，默认关闭。同时调整本系统计费和返回给客户端的缓存创建量，缓存读取不变；内部保留原始上游测量用于计费核对。关闭 Excel / BPS 开关时同时移除此计费选项。
- 修复工具输出编号兼容性、重复错误响应和压缩请求的错误事件；运维错误详情按日志设置保存，并隐藏账号令牌等敏感信息。

## 使用边界

- 模型权限由上游决定，开启不保证解锁任何模型，也不自动换模型。`max`、`ultra`（推理强度档位）转成 `xhigh`；`none`、`minimal` 转成 `low`，用量保留请求档位及实际档位。
- 图片理解支持上游可访问的 HTTPS 图片链接；base64（请求中内嵌图片数据）自动上传到 OpenAI 附件接口并转成官方文件编号。无需对象存储或本站公网取图。客户端直接提供的文件编号及本地路径仍不支持，也不提供图片生成通道。
- 托管工具（上游执行的网页搜索、文件搜索、代码解释器等）不能作为客户端工具执行。网关遇到这些声明、强制工具选择或原生文件/音频内容时，发送前使用原通道，保留工具和参数；这不是失败重试，也不代表原通道有对应模型权限。此前强制要求 BPS 的内部协议测试仍拒绝不支持的调用。仅靠 `previous_response_id`（旧响应编号）续接不支持；需传完整历史。
- 工具回放缓存只在当前服务进程内，最多 1024 项、16 MiB。完整调用历史可按新版规则重建；只有工具结果且缺少对应缓存时会要求新建会话。重启、多实例切换或淘汰可能导致这种情况。没有线程/会话标识时不共享回放缓存，只接受可完整重建的历史。
- 请求失败不会静默切换到另一条协议或重复执行工具请求；流中断不记作账号恢复成功。正常调度仍要求账号可用，开关不会恢复停用账号。

## 验证与排查

### 客户直接上传图片

更新后，使用 Excel 通道的客户继续按原来方式粘贴或上传图片，无需新设置。网关使用所选账号的登录凭证和代理，把图片发送到 `https://bps.openai.com/basispoints/api/attachments`（OpenAI 的 Excel 附件接口），取得 `openai_file_id`（官方文件编号），再在模型请求中用 `file_id` 引用图片。

实现参考了 [excel-codex-bridge 的附件协议](https://github.com/Kaixxrua/excel-codex-bridge/blob/8acc2ccb09840cfc202ee1a718e70aab2ec7e56d/src/excel_codex_bridge/images.py)。本项目实测已有 OpenAI 直接登录授权账号也可以上传和识图；无需读取本机 Excel 登录态。

- 用户消息和工具输出里的内嵌图片均自动转换；已有 HTTPS 图片链接原样转发。客户端继续发送原图，不需要获得或维护官方文件编号。
- 图片发送到 OpenAI，此上传流程不再写本地图片文件，不依赖本站公网域名、临时链接、隧道或对象存储。
- 同一个客户端密钥、同一个上游账号、相同图片内容复用文件编号；账号、客户密钥或上游账号身份变化时分别缓存。同图并发请求共享一次上传，不跨客户共享文件编号。刷新登录令牌不会单独导致重新上传。
- 内存最多缓存 1024 个文件编号，优先淘汰最近最少使用的记录；缓存不保存图片或登录令牌。重启、缓存淘汰或切换上游账号后，重新提交原图会再次上传。单实例最多同时执行 32 个不同图片的上传，同图等待者共用结果；上传超时 120 秒，也响应请求取消。
- 模型协议和图片格式先校验，再上传；支持 PNG、JPEG、GIF、WebP，每张最多 20 MiB、4000 万像素、解码后合计最多 32 MiB。本地不再限制图片张数，保留用户消息和工具结果中的全部图片；重复图片共用上传结果。上述体积/尺寸校验为现有本地资源保护，不是已确认的上游官方限制。上传不能重定向到其他地址，使用与模型请求相同的账号、代理和传输层。
- 上传失败、认证失败、文件编号缺失或非法时明确报错；不省略图片继续回答，不切换普通通道，不自动重放模型请求。上游明确报告文件不存在、编号无效或过期时，删除对应的本地编号缓存，下一次客户端重试会重新上传。
- 会话/轮次标识仍由稳定图片内容占位符计算，不因上传返回的编号变化而重算。缓存命中还受上游账号、历史内容及上游策略影响，不作绝对命中保证。
- **图片改由 OpenAI 保存，不能保证上传后 5 分钟删除。** 此实现没有调用已验证的官方删除接口，也不将内存缓存淘汰当成官方文件删除。
- 旧 `/v1/excel-images`（本站临时取图端点）已移除，旧链接无法再取图。仅保留旧本地临时文件的过期清理：启动时及每分钟清理超过 5 分钟的旧文件，不新建目录、不写新图片，也不触碰异步生图任务结果。已有生成图片对象存储功能不受此变更影响。

### 2026-09-26 客户错误存档回归

- 错误诊断增加 `request_summary`（遍历完整请求得到的结构摘要），记录历史项数、图片数、内容类型和工具目录样本，不含图片正文、会话文本或命令参数。摘要的明细数量有上限，但总数覆盖完整已解析请求。原始加密样本的采集上限不变，摘要不等于完整可重放请求。
- 归档新增 `upload_complete`（上传是否完整）、已接收/声明/缺少字节及采集截断原因。后台错误详情直接显示上传状态和字节数；旧记录没有新字段时保持未知。`request_complete` 仍表示存档是否保留了完整且可读取的请求。
- 请求未收齐、上传超时、连接中断、压缩解码失败分别返回明确错误。缺失字节不能由服务端还原，部分请求不会转发给模型；仍需通过同一请求编号关联入口代理日志定位实际断点。
