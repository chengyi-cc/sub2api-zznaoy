# Astra 网关借票：固定出口版

本次为第一阶段移植，参考 ranxi2001/sub2api 的 v2.9.8（PR #288）：
https://github.com/ranxi2001/sub2api/pull/288

保留来源路由获取、目标两轮门票探针、固定出口亲和、过期重新验证、管理员配置和持久历史。按本项目服务与账号接口重新适配，没有整体合入参考仓库。Prism 不属于本次移植。

## 在哪里开启

管理员侧边栏 → **Astra 网关借票**，页面地址 `/admin/astra-borrow`。默认关闭。

1. 先在账号管理准备两个直接登录授权的 OpenAI OAuth 账号（OAuth 指登录授权凭据），确认账号正常、允许 `gpt-6-astra` 且没有把它映射成其他模型。关闭这两个账号的 Excel 协议。影子账号、个人访问令牌及代理身份账号不适用。
2. 为来源账号配置固定出口代理；也可以在服务器直连出口固定的情况下使用直连。不需要动态 IP。每个请求都更换出口 IP 的代理不适合这个功能。
3. 在借票页面选择一个来源、一个目标，二者不能重叠。来源应是你已确认 Astra 回答质量正常的账号；系统的轻量请求不会替你判断来源的回答质量。
4. 保持“跟随来源代理”开启，有效期先用 230 秒。开启借票并保存，页面会自动获取来源路由并验证目标。
5. 目标显示“可用”后，用只包含目标账号的测试分组发起 HTTP `/v1/responses` 请求，模型使用 `gpt-6-astra`。HTTP 是普通请求连接，可保持原来的流式响应设置。密钥仍使用本项目的用户调用密钥，不需要把来源凭据给客户端。
6. 先检查短文本，再检查工具调用、多轮历史与实际任务效果。门票探针通过只说明本次续接判据通过，不是模型质量或永久可用性保证。

启停借票或切换通道后，建议新建客户端会话；这个功能不会修复旧会话的无效门票。

每类最多选 20 个账号。先选一个来源和一个目标，方便定位结果。既有分组权限、模型白名单和账号调度条件仍生效；借票页面不会替用户密钥换组，也不修改账号模型列表。

## 各个设置的作用

- **启用网关借票**：控制选定目标账号的 Astra 请求。保存关闭后，后续请求恢复原有路径；已经发出的请求不强行中止。
- **来源账号**：用来源自己的凭据发一次极短请求，只有收到完整的 Astra 成功终态及有效 `__oailb`（上游路由 Cookie，即线路标记）才保存候选路由。
- **目标账号**：目标使用自己的凭据，在候选路由上连续发两次短请求。第一轮必须取得 `x-codex-turn-state`（上游续接门票），第二轮带回第一轮的门票；两次都完整成功且第二轮没有换票，才允许借用。来源的凭据和门票不会复制给目标。
- **跟随来源代理**：验证与业务请求使用来源取得路由时的代理。来源直连，目标也直连；关闭时使用目标自己的代理，并在该出口重新验证。代理地址相同不保证公网 IP 相同，请自行确认代理提供固定或粘性出口。
- **路由有效期**：30–240 秒，默认 230 秒。从收到来源响应头开始计算，上游更短的失效时间优先；使用路由不会延长有效期。
- **重新验证**：撤销目标旧的通过结果并重新运行两轮探针。不会仅凭历史成功显示通过。

保存启用后准备一次；路由过期后由下一个业务请求按需重新获取和验证。失败通常有 30 秒冷却，避免连续请求反复探测。同一实例仅执行一组准备探针，已经验证的业务请求可以并发。

## 运行与历史

状态区区分未验证、验证中、可用、失败、过期和关闭，并显示来源、原因及剩余时间。页面刷新只读状态，不触发模型调用。

历史记录保存在数据库，展示来源/目标编号、时间、通过/失败及固定原因码，支持加载更早记录。保留 30 天，清理由后续写入分批执行。Cookie、门票、代理地址、凭据、提示词和模型正文不进入此历史表。历史写入失败会在页面报告。

路由和探针门票只保存在当前进程内存中；重启后重新验证。共享数据库的其他实例能看到配置和历史，但各自获取、验证自己的路由。状态面板显示接收该请求的实例；首次试用建议单实例或固定到同一实例。

验证请求会消耗上游额度，并遵循账号并发和请求频率限制。本版不把这些运维探针计入用户账单；业务请求仍由原有用量及计费流程处理。来源获取、目标探针和借票传输自身都不重放不确定结果的请求。没有可用路由时明确报错，不退回未验证出口。

## 本阶段范围

- 支持普通 HTTP Responses 转发及使用该转发链的兼容入口，借票模型固定为 `gpt-6-astra`。
- 选定目标账号期间明确拒绝原生 WebSocket（双向长连接）请求，避免长连接绕过借票。客户端应使用 HTTP。账号原来的长连接设置不被改写。
- 未接入 WS 固定会话、Mihomo（代理节点管理程序）自动轮换、旧的普通打票系统、自动暂停/移组等调度接管。
- 不支持借票执行独立 compact（上下文压缩）端点；该请求会明确失败。请求其他模型仍沿用原有 HTTP 路径。
- 目标账号后续重新开启 Excel 时，Astra 请求明确报配置冲突，避免绕过借票策略。

## 升级和回退

新增迁移 `245_astra_borrow_history.sql`，只创建借票历史表和时间索引；已有迁移文件不变。配置使用独立设置键 `astra_gateway_borrow_v1`，不覆盖 Excel 设置。

构建需要前端和后端一起更新。上线前备份数据库，由本项目原有迁移机制创建新表。回退前保存关闭借票；本阶段没有自动修改账号开关、模型名单或分组，因此不需要恢复这些账号状态。旧程序不会使用此功能的设置与历史表。

```text
cd backend
go test ./internal/service ./internal/repository ./internal/handler/admin -run TestAstraBorrow -count=1
go test -race ./internal/service -run TestAstraBorrow -count=1
cd ../frontend
pnpm exec vitest run src/views/admin/__tests__/AstraBorrowView.spec.ts src/i18n/__tests__/localeKeyCompleteness.spec.ts

```

离线测试通过不能代替真实来源/目标账号和部署出口上的验收。本次实现不会自动开启线上借票或调用你的真实账号。

本地验证记录：借票服务专项、并发竞态检查、相关 Excel 与长连接回归、历史存储模拟数据库测试、8 项页面及语言检查、前端规范检查与生产构建通过。当前环境没有 Docker（容器运行工具），因此未运行真实 PostgreSQL（关系数据库）的迁移与集成验收；没有部署线上服务器。
